## Known gaps

- Division, `element_at` and `to_date` are detected with a suggested `try_*` replacement but not rewritten. A regex can't safely handle operator precedence.
- The A/B check assumes the job is idempotent and that its output tables can be identified. They are found from `saveAsTable`, `INSERT`, `MERGE` and `CREATE TABLE`, or from the `smct_output_tables` tag. Jobs that write to plain paths need the tag.
- `%run` includes and `dbutils.notebook.run` children aren't followed. Each task's notebook is scanned on its own.
- Jobs with more than 100 tasks depend on the SDK following task pagination in `jobs.get`. Not tried on a job that large.
- Whether `environment_key` is accepted on notebook tasks depends on the Jobs API release. The transformer only sets it on notebook tasks that have dependencies, and `create_with_fallback` retries without it if the API rejects it. The fallback is covered by tests but hasn't met a real rejection yet.
- The allowed `spark.conf.set` keys (`rules.ALLOWED_SPARK_CONFS`) come from the public docs at the time of writing. Edit the set if your release differs.
- Only the job definition is checked for literal secrets, not the notebook code.
- Cost views (L12) are SQL that hasn't run against real `system.billing` data yet.
- 86 offline tests pass against in-memory fakes. `db.py` is thin but has only been exercised for discovery on a live workspace. The rest needs a run on a workspace with classic compute; follow `docs/VERIFICATION.md` and record the result.
